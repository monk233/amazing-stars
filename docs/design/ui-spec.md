# Amazing Stars UI 规范

状态：生效。适用范围：`entrypoints/manager` 管理页与 `src/ui/` 下的全部界面实现。
日期：2026-10-12。维护方式：界面相关的实现、样式、交互与动效改动必须先满足本规范，再提交。

本规范基于当时的界面实现、[产品边界](../../PRODUCT.md)、[视觉候选](./visual-direction.md) 与 [产品设计](../superpowers/specs/2026-10-09-amazing-stars-design.md) 第 10 节整理。规范规定"应该怎么做"，同时记录当前实现与规范的偏离项（见 §15），偏离项不表示已经修复。

## 0. 优先级与边界

规则冲突时按以下顺序裁决：

1. 用户明确指令。
2. 数据安全与隐私边界（不静默取消 Star、不删除分类、不覆盖手动修改、不发送私有资料、凭证不回显）。
3. 可访问性（键盘可达、可见焦点、对比度、减少动画）。
4. 本规范中的硬性规则（标"必须""禁止"）。
5. 视觉偏好与个人风格。

本规范是产品界面规范，不是落地页规范。它不追求营销页的表现力，优先级依次是：能读懂、能操作、能长期使用、最后才是好看。

## 1. 设计立场

**设计读法**：面向中文使用者的本地优先收藏管理工具，语气平静克制，编辑式极简语言，双主题（纸页目录 / 轨道工作台），原生 CSS 语义 token 加 React 组件。

三个旋钮（沿用本仓库既有取值，不照搬落地页基线）：

| 旋钮 | 取值 | 理由 |
| --- | --- | --- |
| DESIGN_VARIANCE | 3 | 工具界面，结构可预测优先于表现欲。对称栅格、对齐的行列、一致的间距。 |
| MOTION_INTENSITY | 2 | 反馈性微动效。管理页长期停留，不做持续动画与滚动编排。 |
| VISUAL_DENSITY | 6 | 收藏列表是数据界面，需要较高信息密度，但不是驾驶舱。控件 40px 高，行距紧凑。 |

由此推导出的三条不变式：

- 界面不靠装饰取胜，靠层级、对齐与留白。
- 动效只服务反馈与状态转换，不服务情绪。
- 任何状态都必须诚实呈现，不用假数据或成功提示掩盖未完成的工作。

## 2. Token 契约

### 2.1 唯一来源与命名

- 语义 token 使用 `--kebab-case` 命名，禁止出现带主题名的 token（不写 `--folio-accent`）。
- 主题色值只定义在 `tokens.css` 的 `:root`（含 `data-theme`、`data-mode` 与两者组合的选择器），组件样式一律通过语义 token 引用。管理页内禁止硬编码 `#hex` 与 `rgb()`。
- 例外只有两处：`@font-face` 的资源路径；设置页主题缩略图的 `--thumb-*` 变量（它是被预览主题的快照，不是当前主题）。
- 新增 token 必须同时补齐四套主题组合：`folio-light`、`folio-dark`、`observatory-light`、`observatory-dark`。缺一套视为未完成。

### 2.2 语义色 token

| token | 语义 | 使用位置 |
| --- | --- | --- |
| `--ground` | 页面底色 | `body`、输入框底色、行 hover 底色 |
| `--paper` | 内容面 | 主区域、卡片、浮层、下拉面板 |
| `--rail` | 导航栏底色 | 侧栏、移动端顶栏 |
| `--ink` | 主文字 | 标题、正文、激活项 |
| `--muted` | 次要文字 | 说明、元信息、未激活项 |
| `--line` | 分隔线与描边 | 1px 边框、行分隔、字段描边 |
| `--soft` | 弱强调底 | 激活项底色、hover 底色、筛选 chip 底色 |
| `--accent` | 唯一强调色 | 主按钮、焦点环、选中态、语义高亮 |
| `--accent-ink` | 强调底上的文字 | 主按钮文字、选中标记 |
| `--error` | 错误与警告 | 内联错误、警告徽标、危险操作文字 |

颜色纪律：

- 每套主题只有一个强调色，界面不得出现第二个具名强调色。
- 强调色饱和度低于 80%，与中性色共存而不是互相争夺。
- 不得混用暖灰与冷灰：folio 走暖灰，observatory 走冷灰，两者不互相借用。
- 阴影用 `color-mix(in srgb, var(--ink) N%, transparent)` 或直接取 ink 色相的低透明值，禁止纯黑阴影。
- 浮层与对话层的阴影保持低透明度、大扩散。全站只允许两级：下拉与提示用 `0 8px 24px` 级别，对话框用 `0 24px 70px` 级别。

### 2.3 主题矩阵

主题通过 `data-theme` 与 `data-mode` 两个属性表达，由 `src/ui/theme.ts` 的 `applyAppearance` 写入 `document.documentElement`：

| 属性 | 取值 | 默认 |
| --- | --- | --- |
| `data-theme` | `folio`（纸页收藏馆）、`observatory`（轨道观测室） | `folio` |
| `data-mode` | `light`、`dark`；`system` 经 `resolveColorMode` 解析后写入 `light` 或 `dark` | `system` |

约束：

- 主题不是明暗别名。两套主题各有独立的明暗取值，都必须单独调色，不得用反相生成。
- `color-scheme` 必须与解析后的模式同步，确保原生控件与滚动条跟随。
- `mode: system` 时监听 `prefers-color-scheme` 变化并实时切换；用户手动选择后不覆盖其选择。
- 新增主题 = 新增一套 token 值 + 在 `Theme` 类型与设置页卡片中登记，不新增 CSS 结构分支。

### 2.4 字体

| 用途 | 取值 | 说明 |
| --- | --- | --- |
| 品牌与展示字标、计数 | `var(--display)` | folio 为 Fraunces（衬线），observatory 为 Space Grotesk（无衬线） |
| 界面正文、控件、按钮 | `'Segoe UI', 'Microsoft YaHei', sans-serif` | 系统 UI 栈，中文优先可读 |
| 代码、快捷键、路径 | `'Cascadia Code', Consolas, monospace` | 只用于 `<kbd>`、`<code>`、标识符 |

硬性规则：

- 不引入新的网络字体来源，不新增自托管字体文件。字体只以 `.woff2` 本地资源打包，`font-display: swap`。
- 展示字体只用于品牌、页标题、计数与几何标识，不用于正文与表单。
- 不把 Inter、Roboto、Open Sans 引入本项目。
- 数据与数字必须带 `font-variant-numeric: tabular-nums`，位置包括计数、分页、时间、状态数字。
- 中文正文行高不低于 1.7；面板内说明文字不低于 1.75。
- 正文字宽上限 62ch 至 70ch。超过时截断而不是拉宽。

### 2.5 字号阶梯

只允许以下档位，禁止出现 13.5px、15.5px 之类的游离值：

| 档位 | 用途 |
| --- | --- |
| 10px | 元信息、时间、极次要标记 |
| 11px | 标签、eyebrow、计数徽标、快捷键 |
| 12px | 辅助说明、面板内文字、菜单项 |
| 13px | 控件文字、列表元信息、正文主力 |
| 14px | 卡片标题、字段标签、主题卡片标题 |
| 16px 至 17px | 面板标题、区块标题 |
| 19px 至 20px | 列表项名称、空状态标题 |
| 25px 至 34px | 页标题、品牌字标、计数 |
| `clamp(28px, 2.1vw, 42px)` | 列表页主标题（唯一允许的流式字号） |

字号下限 10px，任何界面文字不得小于 10px。标题字距使用负值（`-0.02em` 至 `-0.06em`），小标签使用正值（`0.04em` 至 `0.12em`）。

### 2.6 间距

- 基础节奏 8px 的近似阶梯：4、8、12、16、20、24、32、40、48。
- 控件内部允许 6、10、14、18 作为紧凑档，但同一组件内不得混用相邻两档。
- 区块之间的纵向间距用 24 至 48；卡片内边距 18 至 24；侧栏内边距 18 至 28。
- 相邻两个同级元素的间距必须一致，不做逐项微调。
- 底部留白略大于顶部。滚动容器的最后一个子元素要留出与顶部对应的呼吸空间。
- 移动端（≤760px）横向内边距统一 20px。

### 2.7 圆角

| token 建议 | 值 | 用途 |
| --- | --- | --- |
| `--radius-xs` | 3px | 行内标记、标签、快捷键 |
| `--radius-sm` | 5px | 按钮、输入框、选择器、行内小方块 |
| `--radius-md` | 8px | 面板、卡片、列表缩略块 |
| `--radius-lg` | 10px | 对话框、浮层 |
| `--radius-pill` | 999px | 仅状态圆点与圆形图标按钮 |

超出以上档位的圆角值不允许新增。圆角一致性优先于局部审美。

### 2.8 层级

| token 建议 | 值 | 用途 |
| --- | --- | --- |
| `--z-base` | 0 | 常规文档流 |
| `--z-controls` | 3 | 冻结在滚动区之上的控件行 |
| `--z-rail-mobile` | 5 | 移动端顶栏 |
| `--z-menu` | 10 | 下拉菜单、选择器面板 |
| `--z-tip` | 20 | 提示气泡 |
| `--z-dialog` | 60 | 对话框遮罩 |
| `--z-toast` | 70 | 结果提示条 |

禁止使用 999、9999 之类的任意层级。新层必须先在本表登记。

### 2.9 动效与缓动 token

| token 建议 | 值 | 用途 |
| --- | --- | --- |
| `--motion-fast` | 120ms | 颜色、描边、底色的微反馈 |
| `--motion-base` | 140ms | 默认过渡：hover 底色、图标色 |
| `--motion-slow` | 200ms | 浮层出现、卡片抬升 |
| `--ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | 进入与位移 |
| `--ease-feedback` | `ease` | 颜色与透明度 |

超过 300ms 的过渡必须说明理由，并在代码注释中写明它传达的状态变化。

## 3. 布局规范

### 3.1 外壳结构

管理页采用固定外壳加内部滚动：

```
.manager-stage        100dvh，持有 token 与底色，页面本身不滚动
  └ .manager-workspace  两栏栅格，overflow: hidden
      ├ .rail           导航栏，纵向排列，自身可滚动
      └ .workspace-main 主区域，纵向 flex
          ├ .library       收藏页：头部、控件、结果、页脚
          └ .document-view 详情与设置页：整块滚动
```

硬性规则：

- 视口高度只用 `100dvh`，禁止 `100vh`、`height: 100%` 顶替。
- 页面外壳不滚动，滚动只发生在 `.rail`、`.library-results`、`.document-view`、`.filter-panel` 这些明确声明的容器上。
- 每个滚动容器必须写 `overscroll-behavior: contain`，防止滚动穿透。
- 需要稳定宽度的滚动容器使用 `scrollbar-gutter: stable`。
- 结构布局用 CSS Grid，禁止用 flex 百分比数学凑列宽。
- 标签用语义元素：`nav`、`main`、`section`、`article`、`aside`、`button`、`time`。不用 div 堆叠可点击区域。

### 3.2 断点与响应式

| 视口 | 侧栏 | 结果列数 | 主区域内边距 |
| --- | --- | --- | --- |
| ≥2800px | 280px | 3 列 | `clamp(24px, 3vw, 72px)` |
| 1800px 至 2799px | 248px | 2 列 | `clamp(24px, 3vw, 72px)` |
| 1101px 至 1799px | 248px | 1 列 | `clamp(24px, 3vw, 72px)` |
| 901px 至 1100px | 216px | 1 列 | `clamp(24px, 3vw, 72px)` |
| 761px 至 900px | 216px | 1 列 | 收紧内边距 |
| ≤760px | 顶栏（`flex-direction: column`） | 1 列 | 20px 横向 |
| ≤360px | 顶栏紧凑 | 1 列 | 16px 横向 |
| 高度 ≤720px 且宽度 >760px | 侧栏保持 | 1 列 | 纵向间距整体压缩 |

规则：

- 断点只用 1800、1100、900、760、360 与高度 720。禁止新增一次性断点。
- 每个多列布局必须在同一组件内显式声明 `< 760px` 的降级方式，不接受"框架会处理"的假设。
- 移动端不隐藏功能，只更换入口形态：筛选项收进面板，账号选择收进菜单，图标按钮保留 `aria-label`。
- 基准验收视口为 1440×900、1366×768、390×844。改动后必须在这三个尺寸检查主要操作是否仍可见可点。

### 3.3 容器与内容宽度

- 收藏页 `.library` 在超宽屏上限制最大宽度（当前 2800px 至 3400px），避免列表行被拉成一条横线。
- 详情与设置内容 `.document-content` 限宽，正文段落限宽 62ch 至 70ch。
- 表单字段容器上限 620px；设置面板整体上限 880px 至 1080px。
- 禁止内容贴边：任何主区域必须有横向内边距。

### 3.4 页面骨架

- 收藏页：`library-header`（标题、计数、同步状态与按钮）→ `library-controls`（搜索、排序、筛选）→ `active-filters`（已选条件 chip）→ `results-heading` → `library-results` → `library-footer`（统计与分页）。头部与控件区固定，只有结果区滚动。
- 详情页：`page-title` → `detail-heading` → `view-tabs` → `detail-columns`（正文与侧注两栏，侧注 ≤28%）。窄屏侧注折到正文下方。
- 设置页：`settings-tabs`（横向分区）→ `settings-panel`（内容）→ 可选 `settings-subtabs`（子分区）→ `settings-card` 分组。每个面板只承载一类设置。
- 列表行高度与元信息位置必须跨行一致：名称、描述、元信息三段在同一 Y 位置对齐，右侧附加信息右对齐并保持固定列宽。

## 4. 组件规范

组件样式一律写进 `src/ui/library.css`（工作区通用）或 `src/ui/settings.css`（设置页），选择器必须以 `.manager-workspace` 开头。

### 4.1 按钮

| 层级 | 类名 | 用途 |
| --- | --- | --- |
| 主操作 | `.button` | 每屏最多一个，例如"验证并保存""同步收藏" |
| 次级 | `.button.secondary`、`.outline-button` | 撤销、切换、次要提交 |
| 图标 | `.icon-button` | 无文字，必须有 `aria-label` |
| 文字 | `.small-link`、`.back-link` | 低权重动作与返回 |

规则：

- 主按钮底色 `var(--accent)`，文字 `var(--accent-ink)`；次按钮透明底加 `var(--line)` 描边。
- 按钮文字必须单行不换行；标签用动宾结构，2 至 4 个字为主（"同步""重试""保存""新建分类"）。
- 最小点击高度：常规按钮 40px，图标按钮 34px，行内链接 24px。
- hover 只做底色或透明度变化，不做位移；`:active` 允许 `translateY(1px)` 模拟按下。
- `:disabled` 必须降低不透明度并去掉指针手势，同时保留可读性。
- 长任务可以在按钮内显示进度：旋转图标加「处理中 X / Y」，按钮进入禁用态。旋转图标只允许出现在按钮内部，这是 §12「禁止骨架屏以外的加载转圈」的唯一例外。
- 全屏范围内禁止出现两个意图相同但文案不同的动作（"验证并保存"与"连接账号"不得并存于同一屏）。

### 4.2 表单与字段

- 结构固定：`label` 在输入框上方 → 输入控件 → 帮助文本 `field-help` → 内联错误 `inline-error`。
- 禁止用 placeholder 代替标签。
- 输入框态：默认 `1px solid var(--line)`；hover 加深描边；focus 用 `border-color: var(--accent)` 加 3px 半透明外环；disabled 保持对比度并去掉 hover。
- 错误文案写在字段下方，不用 `window.alert`，不用只变色不解释的提示。
- 凭证类字段：默认 `type="password"`，不回显明文，不提供复制按钮，保存后界面不得再展示原值。
- 复选框与单选使用原生控件配合 `accent-color: var(--accent)`，不手写外观。
- 每个字段必须能只用键盘完成填写与提交。
- 非凭证设置默认自动保存：字段停止输入后写入，不再提供保存按钮；凭证类字段（Git 令牌、AI 的 API Key）必须由用户显式提交并验证，自动保存不得触碰它们。

### 4.3 选择菜单（`.select-menu`）

- 触发器使用 `button`，面板使用 `role="listbox"` 或者等价的按钮列表加 `aria-selected`。
- 面板最大高度 220px 并内部滚动，宽度不超过 `min(320px, 80vw)`。
- 键盘必须支持：`ArrowUp`/`ArrowDown` 移动高亮，`Enter` 选中，`Esc` 关闭，关闭后焦点回到触发器。
- 面板的层级使用 `--z-menu`，出现在触发器下方 5px；空间不足时向上翻转并调整锚点。

### 4.4 标签与状态

- 标签 chip 用于展示分类归属与维度标签，圆角 3px 至 4px，字号 11px，底色 `var(--soft)`。
- 可交互标签使用 `aria-pressed`，选中态用 `--soft` 底色加 `--accent` 描边。
- 状态徽标使用标签加圆点表示语义（已连接、待处理、警告），圆点只在有真实状态含义时出现，不得作为纯装饰。
- 状态不得只靠颜色区分，必须同时有文字。

### 4.5 列表行（`.repo-row`）

- 一行展示：缩略标记、归属、名称、描述（最多 2 行）、元信息、右侧附加信息。
- 整行是一个可聚焦的操作目标，hover 用 `var(--ground)` 底色变化表示。
- 描述超出两行截断，用 `-webkit-line-clamp`，不靠改变高度。
- 右侧附加信息列固定宽度，内容右对齐，数字使用 tabular-nums。
- 行与行之间用 1px `var(--line)` 分隔，不额外加卡片边框与阴影。
- 空高亮禁止跳动：hover 只改底色，不改内边距与边框宽度。

### 4.6 卡片与面板（`.settings-card`、`.account`）

- 卡片只在需要表达分组与层级时使用。能用分隔线与留白区分的，不加卡片。
- 卡片形态统一：`1px solid var(--line)` 加 `var(--paper)` 或 `var(--ground)` 底色，圆角 8px 至 9px，内边距 18px 至 24px。
- 禁止卡片套卡片。需要二级分组时用通栏分隔线与小标题。
- 卡片标题用 `h3`，14px 加粗；副说明 12px `var(--muted)`，宽度不超 64ch。

### 4.7 对话框（`.dialog-backdrop`、`.category-dialog`）

- 只用于必须打断流程的确认与表单，能用内联编辑或滑出面板完成的不用对话框。
- 遮罩用 `color-mix(in srgb, var(--ink) 34%, transparent)`，圆角 10px，宽度上限 520px，高度上限 680px 并内部滚动。需要更大空间的内容（长列表、进度与结果）改用独立视图或 §4.10 的结果提示条，不得放大对话框。
- 必须实现：打开时焦点进入对话框，`Esc` 关闭，关闭后焦点回到触发元素，背景内容不可聚焦。
- 破坏性操作（删除分类）的确认按钮必须写明后果（"其中的项目回到未分类"），而不是只写"确定"。

### 4.8 提示（`.info-tip`）

- 提示用于承载原来的一整段指导文字，通过 hover、focus 或点击展开。
- 触发器必须是 `button` 且带 `aria-label`，气泡通过 `aria-describedby` 关联。
- 气泡宽度 `min(300px, 74vw)`，字号 12px，行高 1.7，层级 `--z-tip`。
- 气泡不承载必须的操作入口，它只解释，不要求用户在其中做决定。

### 4.9 空、加载与错误状态

- 加载：骨架屏形状必须与最终内容一致（标签行、标题、卡片块）。骨架动画只允许 1.6s 的横向微光，且在减少动画时完全关闭。
- 空状态：图标或几何标识 + 一句结论 + 一句下一步动作，居中但不置于纯空白之上。
- 错误：内联呈现，说明发生了什么与下一步（"重试""重新填写令牌"），不用 toast 掩盖长期失败。
- 空状态与错误状态禁止使用虚构数据、假统计、假成功提示。
- 局部失败不阻塞整页：不可用的区域单独呈现失败态，其余区域保持可用。

### 4.10 结果提示条（`.toast-stack`）

- 只用于**操作结束后的结果反馈**：成功摘要与失败原因。放在顶部居中作为横幅，宽度 `min(720px, 100vw - 32px)`，层级 `--z-toast`。
- 成功用 `role="status"`，失败用 `role="alert"`；失败条左边框使用 `var(--error)`。
- 进场只动 `opacity` 与 `translateY(-8px)`。横幅会短暂覆盖页面顶部内容，因此不得承载必须点击的内容。
- 最多同时显示 3 条；成功 4 秒、失败 6 秒自动消失，两种都必须提供手动关闭按钮。
- 提示条不承载必须的操作入口，也不用于需要用户决策的内容，那类内容仍按 §4.9 内联呈现。
- 这是 §4.9「错误内联呈现，不用 toast 掩盖长期失败」的限定例外：需要用户处理的长期失败仍然内联，提示条只报告一次性的运行结果。

### 4.11 设置导航（`.settings-tabs`、`.settings-subtabs`）

- 分区使用 `role="tablist"`，配合 `role="tab"`、`role="tabpanel"`、`aria-selected`、`aria-controls`、`tabIndex` 管理焦点。
- 键盘支持 `ArrowLeft`、`ArrowRight`、`Home`、`End`，切换后把焦点移到新标签。
- 切换分区后把滚动容器复位到顶部。
- 只挂载当前分区面板。

## 5. 交互规范

### 5.1 状态矩阵

任何可交互元素必须定义以下状态，缺一不可：

| 状态 | 必须表现 |
| --- | --- |
| 默认 | 与周围中性色协调，文字达到对比度要求 |
| hover | 底色、描边或透明度变化，时长 `--motion-base` |
| active | 轻微下压或底色加深，给出物理反馈 |
| focus-visible | `2px solid var(--accent)` 外轮廓，偏移 2 至 3px |
| 选中 | `--soft` 底色 + `--accent` 描边或文字，并有非颜色的第二线索 |
| disabled | 降低不透明度，改为 `not-allowed` 指针，不可聚焦 |
| loading | 局部骨架或进度文字，按钮变忙碌态并禁止重复提交 |
| error | 内联错误文字，字段描边使用 `var(--error)` |

### 5.2 焦点与键盘

- 焦点环不得被 `outline: none` 抹掉。需要自定义时用等价的可见外轮廓替代。
- 列表行的焦点环允许内缩（`outline-offset: -3px`），但必须可见。
- 全部交互必须可仅用键盘完成，包括分类归属调整这类原本依赖拖拽的操作。
- 拖拽必须提供等价入口（例如详情页的分类与标签选择器），拖拽不是唯一路径。
- 快捷键只在有 `<kbd>` 提示时存在，不得隐藏不可发现的快捷键。

### 5.3 指针交互

- 可点击区域不小于视觉边界，图标按钮的实际热区不小于 34×34。
- 不使用自定义鼠标指针。
- 拖拽中的元素降低不透明度（约 0.55）并保留原位置占位，放置目标使用 `inset` 描边高亮。

### 5.4 反馈时机

- 即时反馈（<120ms）：按下、切换、hover。
- 短任务（<1s）：按钮忙碌态，不弹全局提示。
- 长任务（分页同步、AI 请求）：显示进度与可中断说明，明确写出"不会覆盖原数据""凭证不回显"这类边界。
- 完成提示不加感叹号，不写"恭喜"，只陈述结果。

## 6. 动效规范

### 6.1 动机检验

添加任何动画前必须能用一句话回答"它传达了什么"。合法答案只有四类：层级（引导注意力）、叙事（按顺序揭示内容）、反馈（确认用户操作）、状态转换（表示发生了变化）。回答不出就删掉这个动画。

### 6.2 允许与禁止

- 只允许动画 `transform`、`opacity`，以及颜色类属性（`color`、`background-color`、`border-color`、`box-shadow`）。
- 禁止动画 `top`、`left`、`width`、`height`、`margin`、`padding` 这些触发布局的属性。
- 禁止 `window.addEventListener('scroll', ...)` 与 `window.scrollY` 驱动的状态更新。
- 需要入场效果时用 `IntersectionObserver` 或 CSS，不得使用滚动监听。
- 需要滚动平滑时用 `scroll-behavior: smooth`，并由减少动画偏好覆盖。
- `will-change` 只写在确实会持续动画的元素上，用完即撤。
- 禁止视差、磁吸光标、粒子、3D 翻转、无限循环的装饰动画。管理页只保留：状态骨架微光、面板出现、区块进入、控件反馈。
- 每页最多一处持续动画：加载骨架与按钮内部的进度图标（§4.1）。两者不在同一屏幕上同时出现。

### 6.3 写法约定

- 过渡以渐进增强方式声明，减少动画偏好下不注册过渡：

```css
@media (prefers-reduced-motion: no-preference) {
  .manager-workspace .repo-row { transition: background-color 140ms ease; }
}
```

- 减少动画偏好同时作为兜底，关闭一切动画与过渡：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation: none !important;
    transition: none !important;
    scroll-behavior: auto !important;
  }
}
```

- 区块进入使用 `translateY(12px)` 加 `opacity: 0` 到 `1`，时长不超过 260ms，缓动用 `--ease-out`。
- 列表与宫格使用错峰延迟：`animation-delay: calc(var(--index) * 80ms)`，一次不超过 8 项。
- 交互元素的过渡时长不得超过交互反馈的感知阈值（200ms），超出会被感知为迟滞。

## 7. 可访问性规范

- 对比度：正文与控件文字对背景不低于 4.5:1；18px 以上大字不低于 3:1。焦点环与选中药态同样要满足可见对比。
- 语义：可点击的行用 `button`，导航用 `nav`，`aria-current` 标注当前页，`aria-pressed` 标注开关型控件。
- 图标：装饰性图标写 `aria-hidden="true"`；承载含义的图标必须有文字或 `aria-label`。
- 表单：每个输入都有 `label` 关联；错误区域用 `role="alert"`；状态区域用 `role="status"`。
- 语言：`html` 上声明 `lang="zh-CN"`。
- 跳转链接：存在大量导航时提供"跳到主内容"的隐藏链接。
- 页面标题：管理页 `<title>` 使用中文，包含产品名。
- 减少动画：见 §6.3。
- 视口缩放：不禁止用户缩放，不使用 `user-scalable=no`。
- 文字放大到 200% 时，主要操作仍需可达。

## 8. 内容与文案规范

- 界面语言为简体中文。技术标识（Git、GitHub、Gitee、Token、API Key、Markdown）保留原文。
- 术语固定：收藏、分类、维度标签、手册、同步、快照、凭证、账号、规则。同一概念不在不同页面换词。
  - 项目：指单个被收藏的仓库，界面统一用「项目」，不用「仓库」。
  - 凭证：Git 令牌与 AI API Key 的统称。只有平台官方名称（Access Token、私人令牌、API Key）保留原文，其余文案一律用「凭证」。
  - Lists：GitHub 的远端分类功能，保留英文，且不与中文量词连用（写「远端 Lists」而不是「N 个 Lists」）。
- 不使用 emoji，不使用颜文字。
- 不使用 AI 营销腔（"赋能""无缝""一站式""极致""下一代"）。写具体动作与结果。
- 不写感叹号式成功提示，不写"哎呀""好像出错了"这类卖萌错误提示。
- 错误文案三段式：发生了什么、影响了什么、下一步做什么。例如"本地设置格式损坏，未覆盖原数据。"。
- 空状态文案给出可执行下一步，而不是描述性的"这里什么都没有"。
- 不编造数据。任何数字必须来自真实读取或明确标注为演示内容。
- 时间与相对时间使用本地化格式，配合 `time` 元素与 tabular-nums。
- 状态文案必须与真实状态一致：未连接不写"已就绪"，未同步不写"最新"。
- 标点只用中文顿号、逗号、句号、括号、引号。不使用破折号作为装饰或分隔。

## 9. 图标与品牌资产

- 工作区图标统一来自 `src/ui/WorkspaceIcon.tsx` 的 `shapes` 映射，`viewBox` 固定 `0 0 24 24`，`stroke-width` 统一 1.8，`fill: none`，`stroke-linecap` 与 `stroke-linejoin` 为 `round`。
- 不引入图标库依赖，也不混用多套图标风格。缺图标时在同一映射中按同一笔触补齐。
- 图标尺寸在布局中按层级取 13、14、15、16、19px，同一区域内保持一致。
- 品牌几何标识使用 `WorkspaceArt`，只在空状态或品牌位使用，不作为背景装饰重复出现。
- 扩展图标资源在 `public/icon/`，由 `pnpm icons` 生成，尺寸 16/32/48/96/128。16px 的辨识度问题见 [视觉候选](./visual-direction.md)。
- 品牌字体授权文件保留在 `docs/design/assets/`，不得删除或替换授权文本。

## 10. 代码组织与命名

- 组件文件放 `src/ui/`，与数据层（`src/data/`、`src/git/`、`src/library/`）分离。组件不直接访问扩展存储，通过 hook 或控制器。
- 样式分文件：`tokens.css` 全局基础，`library.css` 工作区通用，`settings.css` 设置页。新增样式必须归入其中之一。
- 类名使用 kebab-case 语义命名（`repo-monogram`、`filter-chip`）。禁止无意义缩写与工具类堆叠。
- 选择器一律以 `.manager-workspace` 或 `.manager-stage` 开头。唯一例外是 `tokens.css`：它承载全局基础（`:root` 变量、`body`、`h1`/`h2`/`p`/`button`/`a`/`kbd` 等裸标签），其他样式文件禁止裸标签选择器与全局泄漏。
- 禁止内联 `style`，唯一例外是运行时计算的 CSS 变量（例如面板可用高度 `--filter-space`）。
- 禁止在组件中硬编码颜色、字号与时长，全部取 token 或固定阶梯值。
- 每个组件必须有中文文档注释说明它负责什么，以及关键可访问性处理。
- Props 类型显式声明，不用 `any`。
- 不引入新的运行时依赖（UI 库、CSS-in-JS、状态库、动画库、图标库）。需要时先取得用户确认。
- 死代码、注释掉的旧实现、调试输出在提交前清除。

## 11. 性能与体量

- 界面交互保持主线程空闲：不做同步重计算，列表分页在数据层完成。
- 视觉资源全部本地：字体、图标、几何标识不请求第三方域名。
- 不做持续重绘的全屏滤镜与噪点层。需要纹理时用静态 CSS 渐变，并限定在固定定位的 `pointer-events: none` 层。
- 扩展包体只增加实际用到的资源，预览页资源不进入扩展构建。
- 首屏不出现布局跳动：骨架、列表行、缩略标记都要预留尺寸。

## 12. 禁止清单

以下模式在本项目中一律禁止：

- 纯 `#000000` 或纯 `#ffffff` 作为大面积底色。
- 第二个强调色、AI 紫蓝渐变、霓虹外发光。
- 大面积渐变按钮、玻璃拟态叠加、装饰性光斑。
- 三个等宽卡片的特性行、无意义的分栏宫格。
- 阴影配边框再加底色三重叠加的"通用卡片"。
- 骨架屏以外的加载转圈（例外：按钮内部的进度图标，见 §4.1）。
- 用 `window.alert` / `window.confirm` 做交互。
- 假数据、假统计、假在线状态、假的"已同步"。
- 只用颜色表达状态、只用 hover 暴露关键操作。
- 破坏性操作无确认、无后果说明。
- 在文档与界面中使用破折号作为装饰性分隔。

- [ ] 键盘可以到达并完成全部操作，焦点环始终可见。
- [ ] 对比度达到 4.5:1（大字 3:1），错误与提示文字同样满足。
- [ ] 加载、空、错误、禁用、忙碌五种状态都已呈现。
- [ ] 动效只用 transform 与 opacity，且能用一句话说明动机。
- [ ] 减少动画偏好下界面完全静态且功能不受影响。
- [ ] 1440×900、1366×768、390×844 三个尺寸下主要操作可见可点。

## 14. 与其他设计参考的关系

本规范吸收了三个前端技能的方向，并按产品界面做了取舍：

- 保留：typography 克制与阶梯化、单一强调色、形状一致性、完整的交互状态、动机驱动的动效、减少动画、可访问性硬性要求、反 AI 套路清单。
- 不采用：落地页的表现型手法（非对称破格栅格、滚动编排、磁性微物理、marquee、图片铺陈）。装饰性数字编号 eyebrow 同样不用，唯一例外是设置页的分区序号（`01`–`04`）：它承担分区顺序与导航含义，不是纯装饰。
- 明确不适用：把整套组件库（Material、Carbon、shadcn）引进来。本项目界面规模有限，原生 CSS 加语义 token 已足够，引库会带来体量与一致性成本。
- 艺术方向仍处于候选状态（详见 [视觉候选](./visual-direction.md)），本规范规定两套主题的实现契约，不代替用户对最终方向的确认。

## 15. 当前实现的偏离项

以下条目是当前代码与本规范的差距，记录在案，不表示已经修复：

1. 焦点管理缺少统一封装：提示气泡、拖拽与对话框各自处理焦点，没有共用工具。
2. 尚无「跳到主内容」链接。
3. `WorkspaceShell.tsx` 同时导出页面外壳与项目详情两个组件，未按单一职责拆分。
4. CSS 类名的语义边界仍不清晰：`.tag`、`.tag-filter`、`.meta-tag`、`.filter-chip` 都在表达「标签」；`.manager-stage`、`.manager-workspace`、`.workspace-main` 都在表达容器层级。重命名会牵动大量选择器与组件，尚未收敛。

2026-10-12 已修复并从此表移除：颜色来源重复（统一到 `tokens.css` 的 `:root`，并按 4.5:1 调整了浅色主题的 `--muted`）、圆角游离值、动效与层级未变量化、非阶梯字号、硬编码阴影色。
